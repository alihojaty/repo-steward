# PR / MR workflow

1. **Resolve endpoints.** Identify the actual host, source repo/ref, source SHA, target repo/ref and target SHA. Upstream tracking is evidence, not proof of the desired base. Fork, stacked branch, maintenance and backport PRs often have different targets. Never reveal credential-bearing remotes. No network available? Use explicitly identified local refs, mark freshness unknown, draft only. If base is ambiguous, ask rather than defaulting to the host's primary branch.
2. **Inspect the full change.** Resolve the refs to verified commit IDs first. Inspect `git merge-base <base-sha> <head-sha>`, `git log <base-sha>..<head-sha>` and `git diff <base-sha>...<head-sha>` (names/stat first). No common base or insufficient shallow history → stop and explain; seek permission if more history is needed. An empty effective diff is not a useful PR. Call out unrelated commits, already-merged work, dependent PRs and excessively broad scope. Working-tree edits are not part of a committed PR diff.
3. **Draft for a reviewer.** Prefer the repo template; otherwise adapt [the fallback](../assets/pr.md). Explain the behavior change, evidence, what wasn't tested and where to start review. Include migration order, compatibility, UI evidence, feature flag or rollback steps only where relevant. Don't expose private data in examples. Suggest actual owners, real labels and linked issues only when verified. Use the team's merge convention; for squash merges the title/body may become the permanent history.
4. **Separate draft from publication.** Show proposed destination and action. Pushing a branch, creating/updating a PR, marking ready and merging each have different effects. If explicitly authorized for those operations, verify refs right before writing; do not use a convenience command that silently pushes, forks or creates a branch. For pushes specify source and destination explicitly and allow only fast-forward/no-op by default. Verify remote head afterward. If push rejected, stop rather than forcing. For PR creation, first look up open requests by both repo identities and head/base; reuse when appropriate, do not overwrite reviewer/maintainer edits. Prefer Draft when readiness or checks are incomplete. Never auto-merge from a request to open a PR.
5. **Verify readiness.** Distinguish checks on the PR head from checks on an integrated/queue result. Verify required approvals, latest head, unresolved threads, current mergeability and branch protection through the host; if unavailable, report unknown. Local review is not owner approval. Respect queue policy and stale-review invalidation. Do not resolve another reviewer's thread unprompted. Report check name/state/revision and sanitized PR link when actually available.
6. **Reconcile retries.** After a timeout query the branch or PR by identity before retry. If host read access is unavailable, output a ready-to-paste title/body, known local SHAs and a manual verification list; do not claim an object exists.
