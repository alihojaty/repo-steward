# Scoped local commits

## Before staging

Resolve HEAD, branch, known base and any worktree-specific operation markers. Distinguish (A) HEAD → index, (B) index → working tree and (C) untracked paths. Inspect names/sizes first, then only necessary diffs in a trusted private environment. For programmatic parsing use `-z`; for literal path selection use `git --literal-pathspecs … -- <path>` with argument arrays, not shell globs. Include both sides of renames when reasoning about scope. Never stage an untracked directory recursively without reviewing its contents. Do not use a checkout/reset/stash to tidy up.

- Unrelated or unclear staged content → stop before touching the index. Show the conflicting paths safely and ask the user to isolate the intended change. A request to commit path A does not include B just because B is staged.
- Same file, multiple intentions → use only explicitly reviewed hunks; never invoke interactive TTY commands such as `git add -p`. If clean separation cannot be performed deterministically and safely, propose a split, stop and ask the user to stage the intended hunks. Never substitute the entire working file for a staged partial edit.
- Existing staged work exactly matches requested scope → use the index as-is. A request for a message is not a request to stage or commit.
- Clean index and clean worktree → report no-op. Intentionally empty commits need their own reason and authorization.
- Detached HEAD, non-fast-forward situation, unexpected branch, unresolved conflict, in-progress operation or incompatible index state → stop. Do not switch branches, pull or complete someone else's operation to make a commit possible. For a deliberately requested initial commit verify unborn branch and file allowlist.

## Prepare, validate, commit

1. Split by independently reviewable intent. Keep a fix with its regression test; separate large generated/formatting changes. In monorepos identify changed packages, shared libraries and affected reverse dependencies; scope tests accordingly.
2. Record starting HEAD and staged scope. Stage only approved paths/hunks. Verify final `git diff --cached --stat`, relevant staged diff and `git diff --cached --check` (the latter is not a test suite). Check for unintended deletions, file mode changes, generated drift, private material, large objects and changed submodule pointers. Use existing approved local secret scanner when available; don't print matches or claim full secret coverage from a filename check.
3. Use project-declared checks in a trusted environment. Record command, outcome and tested state. If unstaged/untracked inputs influence a test, report **working-tree test only**. Use CI on the exact candidate SHA for stronger evidence. Never silently install tools, edit tests/hooks or fix unrelated failures. A required check that fails blocks readiness; if execution is unavailable, explain rather than reporting green.
4. Derive the message from the reviewed diff. Match accepted project style. If Conventional Commits is established, use `type(scope): effect` with real scope, breaking-change note and migration when needed. Body: why the change exists or why the implementation isn't obvious. Reference real issues only. Respect signing and DCO policy; never invent an identity, sign-off, bypass or lower signing requirements. If `signing_configured` is true (or signing is required) and non-interactive signing blocks or fails (e.g., pinentry or hardware key prompt), stop and report rather than disabling signing or retrying blindly.
5. Immediately before commit revalidate planned branch/HEAD and exact index tree (in this authorized **write mode**, `git write-tree` gives an object ID). On drift, stop. Commit the reviewed index, not paths or `-a`. Use separate arguments or a message file, never interpolate user text into shell code. Let hooks run; if they fail or modify state, inspect and report, don't retry blindly.
6. Verify resulting parent(s), tree versus reviewed tree, changed paths and final status. If a hook or another process changed the result, disclose and stop; do not silently amend. Return SHA, subject, checks and leftover work. Do not push.
